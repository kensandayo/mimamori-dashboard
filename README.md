# 宇都宮市 見守り支援MAP（地域見守り・施策検討支援システム）

公開統計データを用いて**地区単位**の見守りニーズを可視化し、自治体職員の**施策検討**を支援するダッシュボードです。
高齢福祉課・地域包括ケア推進課・民生委員事務局などが、庁内会議や見守り計画の立案でそのまま利用できることを目指しています。

> **本システムは個人を判定するものではありません。**
> 分析対象はあくまで「地区」であり、個人情報は扱いません。AIやシステムが施策を決定するのではなく、
> 自治体職員が施策を検討するための参考情報を提示します。他自治体の施策事例も「検討候補」であり、
> 導入を推奨するものではありません。最終判断は必ず自治体職員が行ってください。

## 3. 評価項目をコードに固定しない仕組み（★最重要）

このシステムの評価項目（高齢化率・移動系・配食…）は、Pythonコードの中にif文で
書かれているのではなく、`data/parameter_master.csv` というマスタファイルで管理しています。

| 列名 | 内容 |
|---|---|
| param_id | 内部的に使う安定したID（重み・保存パターンの紐付けに使用。表示名を変えても壊れない） |
| label | 画面に表示する項目名 |
| csv_column | 地区データCSV（sample_data.csv）側の列名 |
| unit | 単位（%、指数(0-100) など） |
| risk_direction | positive=高いほど課題／negative=高いほど良い |
| weight | 初期重み（0〜1、有効な項目の合計が1.0になるように） |
| description / source | 説明・出典 |
| active | スコア計算に使うかどうか |

`utils/parameter_loader.py` の `load_active_parameters()` がこのCSVを読み込み、
`scoring.py` をはじめ全ページがこの結果だけを見て動くように作られています。
そのため、**「設定・データ管理」→「評価項目管理」画面から項目を追加・編集・削除するだけで、
マップ・ランキング・比較・地区詳細・シミュレーション・総合スコア・AI相談すべてに自動的に反映されます**。
コードの変更は一切不要です。

新しい項目を追加すると、対応するCSV列が地区データに無い場合は仮の値（50点）で自動的に列が
追加されます（アプリが壊れないための安全策です）。「データ管理」タブから実際の値に更新してください。

## 4. 他自治体施策マスタ（data/policy_master.csv）

「確認候補」となった評価項目に対して表示する、他自治体の実際の取り組み事例のマスタです。
`category`列が評価項目の`param_id`と一致する行が、その項目の参考事例として自動的に表示されます
（`utils/policy_loader.py`）。新しい評価項目・新しい施策を追加しても、表示ロジック側の
コード変更は不要です。

### 列構成

| 列名 | 内容 |
|---|---|
| category | 評価項目の`param_id`と対応させる分類（例：`mobility`） |
| municipality / prefecture | 自治体名・都道府県名 |
| policy_name | 施策名 |
| description | 制度の概要 |
| target | 対象者 |
| cost | 利用料金・自己負担額（公式ページに記載がない場合は「公式ページで確認できず」） |
| frequency | 利用回数・頻度の上限等（同上） |
| features | 制度の特徴 |
| url | 自治体公式ページのURL（推測での作成はしていません） |
| source | 情報源（自治体公式サイト名） |
| updated_at | 情報確認日 |

### 登録内容

Web検索・公式ページの内容確認により実在を確認した12件を、4分野×3自治体で登録しています
（移動系：小山市・久喜市・朝来市／配食：広島市・豊島区・深谷市／緊急通報：東大阪市・長野市・
広島市／日常生活用具：東大阪市・広島市・弥富市）。**すべて市区町村公式サイト（`.lg.jp`等）の
内容のみを情報源とし、ブログ・まとめサイト等は使用していません。** 料金・利用回数が公式ページで
確認できなかった項目は、推測で埋めず「公式ページで確認できず」としています。

**掲載情報は確認時点のものであり、内容が変更・廃止されている場合があります。実際の検討時は
必ず`url`列の公式ページでご確認ください**（画面上にも「情報確認日」を表示しています）。
医療アクセス・高齢化率・単身高齢者向けの事例は、現時点では未登録です（該当する評価項目の
確認候補が表示されても、参考事例欄には「現在、この評価項目に対応する参考事例は登録されていません。」
と表示され、エラーにはなりません）。

### 今後CSVへ施策を追加する方法

`data/policy_master.csv` に、上記の列構成に従って1行追加するだけで、対応する評価項目の
「確認候補」が表示されたときに自動的に参考事例として表示されます。コードの変更は不要です。
`category`列は、追加したい評価項目の`param_id`（`parameter_master.csv`の1列目）と
一致させてください。同じ`category`の行が2件以上になると、地区詳細画面に「事例を比較する」
という比較表（自治体・施策名・対象・料金・利用回数・特徴）が自動的に表示されます。

## 5. 評価パターン（data/patterns.json）

重みの組み合わせ（例：標準／移動重視／見守り重視）を保存・切り替えできます。
サイドバー上部のプルダウンから切り替えると、スコア・ランキング・マップ・地区詳細・
改善優先候補・施策候補が自動的に再計算されます。「設定・データ管理」→「評価パターン管理」
から、現在の重みを新しいパターンとして保存したり、既存パターンを削除したりできます。

---

## 6. 改善優先候補・施策候補の考え方

各評価項目を「高いほど良い」共通の0〜100点スケールに変換した**健全度スコア**を使って、
地区ごと・市全体で「どの項目の改善余地が大きいか」を判定します（`get_indicator_health_scores`）。
このスコアが低い項目について、`policy_master.csv`から関連する他自治体施策を検索し、
「◯◯地区では△△に改善余地があるため、以下の施策が検討候補として考えられます」という
非断定的な表現で表示します（「導入すべき」とは表示しません）。

---

## 7. シミュレーション（What-if分析）

「デマンド交通を導入したら+10点」のような根拠のない自動加点は行いません。
任意の評価項目を選び、「改善後の想定値」（0〜100点の健全度スコア）をスライダーで指定すると、
その値まで改善したと仮定した場合の総合スコア・順位・地図を再計算して表示します。
想定値はあくまで職員が設定する仮定値であることを、画面上に明記しています。

## 8. AI相談機能

「AI相談」画面では、選択した地区（＋比較地区）のデータのみをOpenAI APIに送信し、
チャット形式で質問できます。CSV全体は送信しません。コスト最適化のため、
システムプロンプトの簡潔化・出力トークン数の制限・同一質問のキャッシュ・
1日あたりの利用回数上限（既定50回、`.env`の`DAILY_AI_LIMIT`で変更可）を実装しています。
詳細は `services/ai_service.py` を参照してください。

## 9. 今後の拡張方法

- **新しい評価項目を追加したい** → コード変更不要。「評価項目管理」画面、または
  `data/parameter_master.csv` を直接編集してください。
- **新しい施策事例を追加したい** → `data/policy_master.csv` に行を追加してください
  （`category`をparam_idに合わせること）。
- **新しい評価パターンを追加したい** → 「評価パターン管理」画面から保存、または
  `data/patterns.json` を直接編集してください。

## 10. 本システムの限界（免責事項）

- 公開統計データを基にしています。地区全体の傾向を示す参考情報です。
- 個人を判定するものではありません。最終判断は自治体職員が行います。
- 本スコアは地域の状況を比較・検討するための参考指標であり、行政サービスの良し悪しを
  正式に評価する点数ではありません。
- 他自治体の施策事例は、宇都宮市で施策を検討する際の参考情報です。他自治体が実施している
  ことをもって導入を推奨するものではありません。
- 同梱の `data/sample_data.csv` はデモ用のサンプル値であり、実際の統計値ではありません。
