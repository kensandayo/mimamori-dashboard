# 宇都宮市 見守り支援MAP（地域見守り意思決定支援システム）

公開統計データを用いて **地区単位** の見守りニーズを可視化し、自治体職員の意思決定を支援するダッシュボードです。
高齢福祉課・地域包括ケア推進課・民生委員事務局などが、庁内会議や見守り計画の立案でそのまま利用できることを目指しています。

> **本システムは個人を判定するものではありません。**
> 分析対象はあくまで「地区」であり、個人情報は扱いません。AIによる自動判定システムではなく、
> 自治体職員の意思決定を支援するためのツールです。最終判断は自治体職員が行います。

---

## 1. 環境構築・起動方法

### 必要環境
- Python 3.9 以上を推奨

### セットアップ手順

```bash
# 1. 仮想環境を作成（任意）
python -m venv venv
source venv/bin/activate      # Windowsの場合: venv\Scripts\activate

# 2. 必要なライブラリをインストール
pip install -r requirements.txt

# 3. アプリを起動
streamlit run app.py
```

起動後、ブラウザで `http://localhost:8501` が自動的に開きます。

### 画面ファイル名を英数字にした理由（文字化け対策）

以前はファイル名に日本語・絵文字を使っていたため、実行環境によってはサイドバーの
メニュー表示が文字化けすることがありました。現在は `app.py` の中で
`st.navigation()` / `st.Page()` を使い、

- ページファイル名：`1_dashboard.py` のように、番号＋半角英数字・アンダースコアのみ
- サイドバーに表示される日本語タイトル：`app.py` 内のPython文字列として直接指定

という構成にすることで、画面上の表示は日本語のまま、文字化けの原因を構造的に
排除しています。すべてのファイルはUTF-8で保存されています。

## 3. データについて（標準データはCSV）

このアプリは `data/sample_data.csv` を起動時の標準データとして読み込みます
（`utils/data_loader.py` の `load_default_data()`）。以前のようにPythonコードで
ダミーデータを毎回生成する方式は廃止しました。

**`data/sample_data.csv` の中身を書き換えれば、コードを一切変更せずに表示内容が変わります。**
今後、宇都宮市の公開データに置き換える場合も、同じ列構成のCSVでこのファイルを
上書きするだけで移行できます。

### CSV列構成

| 列名 | 説明 | 値の範囲 |
|---|---|---|
| 地区名 | 地区の名称（重複不可） | 文字列 |
| 高齢化率 | 65歳以上人口の割合 | 0〜100（%） |
| 単身高齢者割合 | 高齢者のうち一人暮らし世帯の割合 | 0〜100（%） |
| 医療アクセス | 医療機関へのアクセスしやすさ指数（高いほど良い） | 0〜100 |
| 公共交通 | 公共交通の利便性指数（高いほど良い） | 0〜100 |
| 緯度 | 地区代表点の緯度 | 日本国内の範囲 |
| 経度 | 地区代表点の経度 | 日本国内の範囲 |

データ出典・対象年度・更新日は `utils/config.py` の `DATA_SOURCE_NAME` /
`DATA_TARGET_YEAR` / `DATA_UPDATED_AT` に定義されており、「設定・データ管理」画面と
ダッシュボードに表示されます。実データに差し替える際はあわせて更新してください。

「設定・データ管理」画面からは、CSVアップロード・画面上での直接編集・CSVダウンロードが
でき、地区数はCSVの行数に応じて自動的に決まります（固定されていません）。

### 入力チェック

CSVアップロード・画面編集のいずれの場合も、以下を自動チェックします（`utils/validation.py`）。

- 必須列の不足
- 数値以外の値の混入
- 欠損値
- 割合(%)列が0〜100の範囲外
- 緯度・経度の欠損／範囲異常

## 4. スコアの計算方法

総合スコア（0〜100点）は、以下の考え方で算出しています（`utils/scoring.py`）。

1. 高齢化率・単身高齢者割合は「値が高いほど見守りニーズが高い」指標としてそのまま使用します。
2. 医療アクセス・公共交通は「値が高いほど見守りニーズが低い」指標のため、`100 - 値` として
   自動的に反転してから使用します。
3. 上記4つの指標を、設定画面で指定した重み（初期値：高齢化率30% / 単身高齢者割合30% /
   医療アクセス20% / 公共交通20%）で加重平均し、総合スコアとします。
4. 優先度（高・中・低）は、全地区のスコア分布のうち上位25%を「高」、下位25%を「低」、
   それ以外を「中」として自動的に分類します（固定の点数しきい値ではなく、データに応じて
   相対的に決まります）。

重みは「設定・データ管理」画面のスライダーからいつでも変更でき、合計値を確認しながら
調整できます。変更内容は地図・ランキング・比較・地区詳細など全画面に即時反映されます。

## 5. 自動分析コメント・推奨される対応例について

- **自動分析コメント**は、各地区の指標値と全地区平均との差を計算し、一定以上の差がある
  指標について「〇〇が市平均より△△ポイント高い（低い）」という文章をルールベースで
  自動生成しています（`generate_analysis_comments()`）。AIによる判定ではなく、
  あらかじめ決めたルールに基づく機械的な差分説明です。
- **推奨される対応例**も同様にルールベースで、スコアへの寄与が大きい指標に応じて
  対応する施策例（地域包括支援センターとの連携、巡回診療の検討など）を提示しています
  （`generate_recommendations()`）。

これらはあくまで参考情報です。最終判断は必ず自治体職員が行ってください。

## 6. シミュレーション（What-if分析）

「もしこの施策で医療アクセスが〇〇改善したら」といった仮定に基づき、スコア・順位・
地図がどう変化するかを試算する機能です（`utils/simulation.py`）。

- 改善量はすべて **仮定値** であり、実際の施策効果を保証するものではありません。
- 試算後は対象地区のスコア・順位に加えて、地図も再計算後の優先度で再描画されます。

## 8. 今後の拡張方法

### 新しい指標を追加したい場合（例：空き家率、災害リスク、スーパー距離、認知症率など）

1. `utils/config.py` の `INDICATORS` リストに、新しい指標の情報（列名・表示名・単位・
   リスクの向き・説明・出典・重みキー）を追加します。
2. `DEFAULT_WEIGHTS` に新しい重みキーを追加し、既存の重みと合計が1.0になるよう調整します。
3. `utils/config.py` の `REQUIRED_COLUMNS` に新しい列名を追加し、CSVの必須列として
   扱われるようにします。
4. `data/sample_data.csv` に新しい列の値を追加します。

上記の対応により、スコア計算・自動分析コメント・推奨される対応例の各ロジックは
共通処理として再利用され、大きな改修なく新指標に対応できる設計にしています。

### シミュレーション機能の拡張

`utils/simulation.py` の `simulate_improvement()` に、新しい指標のdelta引数を
追加することで対応できます。

## 10. 本システムの限界（免責事項）

- 公開統計データを基にしています。
- 地区全体の傾向を示す参考情報です。
- 個人を判定するものではありません。
- 最終判断は自治体職員が行います。
- 同梱の `data/sample_data.csv` はデモ用のサンプル値であり、実際の統計値ではありません。
  実運用時は必ずCSVアップロード機能から実データに差し替えてください。
