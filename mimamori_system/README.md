# 地域見守り意思決定支援システム（プロトタイプ）

公開統計データを用いて **地域単位** の見守りニーズを可視化し、自治体職員の意思決定を支援するためのプロトタイプシステムです。

> **本システムは個人を判定するものではありません。**
> 分析対象はあくまで「地区」であり、個人情報は扱いません。最終的な支援の判断は自治体職員が行うことを前提に設計されています。

---

## 1. 目的

- 限られた人員・予算の中で、どの地域を優先して見守り・福祉施策の対象とすべきかを検討するための「意思決定支援ツール」です。
- 完成品ではなく、自治体職員や企業担当者に実際に触ってもらい、フィードバックを得るための**高品質なプロトタイプ**として設計しています。

---

## 2. 環境構築・起動方法

### 必要環境
- Python 3.9 以上を推奨

### セットアップ手順

```bash
# 1. 仮想環境を作成（任意）
python -m venv venv
source venv/bin/activate      # Windowsの場合: venv\Scripts\activate

# 2. 必要なライブラリをインストール
pip install -r requirements.txt

# 3. アプリを起動
streamlit run app.py
```

起動後、ブラウザで `http://localhost:8501` が自動的に開きます。

## 4. CSVデータ形式

以下7列を持つCSVファイルであれば、地区数を問わずアップロードできます（「設定・データ管理」画面から）。

| 列名 | 説明 | 値の範囲 |
|---|---|---|
| 地区名 | 地区の名称（重複不可） | 文字列 |
| 高齢化率 | 65歳以上人口の割合 | 0〜100（%） |
| 単身高齢者割合 | 高齢者のうち一人暮らし世帯の割合 | 0〜100（%） |
| 医療アクセス | 医療機関へのアクセスしやすさ指数（高いほど良い） | 0〜100 |
| 公共交通 | 公共交通の利便性指数（高いほど良い） | 0〜100 |
| 緯度 | 地区代表点の緯度 | 日本国内の範囲 |
| 経度 | 地区代表点の経度 | 日本国内の範囲 |

アップロード・編集時には自動的に以下のチェックが行われます。

- 必須列の不足
- 数値以外の値の混入
- 欠損値
- 割合(%)列が0〜100の範囲外
- 緯度・経度の欠損／範囲異常

画面上の表（データエディタ）で直接編集することもでき、編集後は即座に再計算されます。編集後のデータはCSVとしてダウンロードできます。

## 5. スコアの計算方法

総合スコア（0〜100点）は、以下の考え方で算出しています。

1. 高齢化率・単身高齢者割合は「値が高いほど見守りニーズが高い」指標としてそのまま使用します。
2. 医療アクセス・公共交通は「値が高いほど見守りニーズが低い」指標のため、`100 - 値` として自動的に反転してから使用します。
3. 上記4つの指標を、設定画面で指定した重み（初期値: 高齢化率30% / 単身高齢者割合30% / 医療アクセス20% / 公共交通20%）で加重平均し、総合スコアとします。
4. 優先度（高・中・低）は、全地区のスコア分布のうち **上位25%を「高」、下位25%を「低」、それ以外を「中」** として自動的に分類します（固定の点数しきい値ではなく、データに応じて相対的に決まります）。

重みは「設定・データ管理」画面のスライダーからいつでも変更可能で、変更内容は全画面に即座に反映されます。

## 6. 判定理由・推奨施策について

- **判定理由**は、各地区の指標値と全地区平均との差を計算し、一定以上の差がある指標について「〇〇が市平均より△△ポイント高い（低い）」という文章をルールベースで自動生成しています。
- **推奨施策**も同様にルールベースで、スコアへの寄与が大きい指標に応じて対応する施策例（地域包括支援センターとの連携、巡回診療の検討など）を提示しています。

これらはあくまで参考情報であり、AIによる自動判定や個人への介入を意味するものではありません。最終判断は必ず自治体職員が行ってください。

## 8. 今後の拡張方法

### 新しい指標を追加したい場合（例: 空き家率、災害リスク、スーパー距離、認知症率など）

1. `utils/config.py` の `INDICATORS` リストに、新しい指標の情報（列名・表示名・単位・リスクの向き・説明・出典・重みキー）を追加します。
2. `DEFAULT_WEIGHTS` に新しい重みキーを追加し、既存の重みと合計が1.0になるよう調整します。
3. `utils/config.py` の `REQUIRED_COLUMNS` に新しい列名を追加し、CSVの必須列として扱われるようにします。
4. `utils/validation.py` の数値チェック対象に必要であれば追加します。
5. サンプルデータ（`utils/data_loader.py` の `generate_sample_data()`）にダミー値の生成処理を追加します。

上記の対応により、スコア計算（`scoring.py`）・判定理由・推奨施策の各ロジックは共通処理として再利用され、大きな改修なく新指標に対応できる設計にしています。

### シミュレーション機能の拡張

`utils/simulation.py` の `simulate_improvement()` に、新しい指標のdelta引数を追加することで対応できます。

## 9. 本システムの限界（免責事項）

- 公開統計データを基にしています。
- 地域全体の傾向を示す参考情報です。
- 個人を判定するものではありません。
- 最終判断は自治体職員が行います。
- 同梱のサンプルデータはデモ用のダミー値であり、実際の統計値ではありません。実運用時は必ずCSVアップロード機能から実データに差し替えてください。
